# Security review

Overall Risk Verdict: High. The application robustly enforces a read-only stance against external network threats via strict `127.0.0.1` binding and `Host`/`Origin` checks. However, a critical command injection flaw exists in a mutating route that fails to verify the required capability token, leaving the system open to local unauthorized code execution.

**SEV-Critical** — packages/server/src/api/lab.ts:445 — Command Injection via `model` — `POST /api/lab/launch` accepts a `model` string from the JSON body and passes it unvalidated to `rhizomorph lab fork`. This flows to `workmuxAddArgv` (packages/server/src/lab/fork.ts:133), which dangerously concatenates it into a shell string: `argv.push('-a', \`bash scripts/lane-agent.sh ${treatment.model}\`)`. Because `workmux add -a` passes this to a shell in a tmux pane, any shell metacharacters in `model` are evaluated. — Exploit path: A local attacker sends `POST /api/lab/launch` with `arms: [{ model: "\"; open Calculator; #" }]`. The resulting command `bash scripts/lane-agent.sh ""; open Calculator; #` executes immediately on the host. — Fix: Validate that `model` contains only safe alphanumeric characters (e.g., `/^[a-zA-Z0-9.-]+$/`), or alter `workmux` invocation to strictly use an arguments array without shell interpolation.

**SEV-High** — packages/server/src/api/lab.ts:553 — Unauthenticated Laboratory Launch Route — Despite documentation (`api/security.ts`) claiming mutating routes require a capability token, `POST /api/lab/launch` completely lacks the `requireCapabilityToken` middleware. — Exploit path: Any local process (or a CSRF payload if Origin headers are omitted or forged by a non-browser client) can hit this endpoint without the process-specific token to launch workloads, burn Claude credits, or trigger the aforementioned command injection. — Fix: Add the preHandler to the route: `app.post('/api/lab/launch', { preHandler: requireCapabilityToken(ctx.capabilityToken ?? '') }, async (request, reply) => { ... })`.

**SEV-High** — packages/server/src/api/rotate.ts:20 — Unauthenticated Session Rotation Route — Similar to the launch route, `POST /api/rotate` omits the capability token check, violating the access control assumptions defined in `SECURITY.md`. — Exploit path: A malicious local script repeatedly sends `POST /api/rotate` requests, terminating active sessions and spamming disk space with new recording files without authorization. — Fix: Apply the capability token middleware: `app.post('/api/rotate', { preHandler: requireCapabilityToken(ctx.capabilityToken ?? '') }, async (_request, reply) => { ... })`.

**SEV-Medium** — packages/server/src/api/lab.ts:444 — CLI Argument Injection via `lane` — `launchExperiment` passes the user-supplied `request.lane` as the first positional argument to `runLabCliOnce`: `const argv = ['fork', request.lane, '--path', options.repoPath, ...]`. The internal CLI parser (`packages/server/src/cli/args.ts:79`) allows flags to appear anywhere. If `request.lane` is prefixed with a hyphen (e.g., `--path`), it is erroneously parsed as a flag instead of a positional argument. — Exploit path: An attacker sets `request.lane` to `--path`. The CLI parser treats this as the `--path` flag, consumes `options.repoPath` as its argument, and shifts positionals. This corrupts the intended command, potentially manipulating paths or triggering logic errors. — Fix: Enforce the end of flags by placing `--` before positionals when programmatically building `argv`: `const argv = ['fork', '--path', options.repoPath, '--at', request.checkpointId, '--arms', '1', '--launch', '--', request.lane]`.

**SEV-Low** — SECURITY.md — Read-Only Data Exposure on Shared Hosts — `SECURITY.md` correctly states that read-routes bind safely to loopback. However, they are exempt from the capability token by design. If a prompt-injected agent writes sensitive secrets (AWS keys, etc.) to the Claude Code log, the dashboard broadcasts them in plain text. — Exploit path: Any unprivileged local user sharing the same machine can query `GET /api/sessions` or view the static frontend to harvest credentials leaked by the agent. — Fix: Update `SECURITY.md` to clarify the risks on multi-user systems. If isolation is needed, consider protecting `GET` routes with the capability token.
