## Findings

Ordered by severity. Findings already covered by an open issue are named as
such and are not restated as new.

### BLOCKER

**1. Rename-in-place always 401s — tracked as [#249](../../issues/249).**
`api/label.ts:38` gates `POST /api/label` behind `requireCapabilityToken`; the
token is minted in-process at `server/build-app.ts:67` and reaches neither
`/api/meta`, the web source, nor the built bundle. `recordings/label.ts:79-83`
sends only `Content-Type`, and its `LabelFetchLike` type (`:34-37`)
structurally cannot carry another header. Every save fails, on every boot, for
every operator, while `README.md:203` documents the control as working.

*Verified by execution.* Booted the real CLI against a scratch repo and sent
exactly what the browser sends, with a real session id from `GET /api/sessions`:

```
POST /api/label  {"sessionId":"1786061790707","label":"renamed-by-audit"}
→ 401  missing or invalid x-rhizomorph-capability header
```

The same boot confirmed the asymmetry behind [#234](../../issues/234):
`POST /api/rotate` returned **200** with no token (it rotated the session), and
`POST /api/lab/launch` reached body validation at **400**. The one route the UI
needs is the only one gated.

### HIGH

**2. The lab console's no-live-fleet law walks 5 of its 17 source files, and a
file it never reads already violates it.**
`packages/web/src/lab/no-live-fleet-law.test.ts:36-40` uses a non-recursive
`readdirSync(LAB_DIR)`. `lab/` has 5 top-level source files and 12 more under
`branching/` (2), `compare/` (7) and `launch/` (3). The vacuity guard at `:45`
(`toBeGreaterThan(3)`) passes on the 5 it can see, so the check added for
exactly this risk does not fire.

Not hypothetical: `packages/web/src/lab/branching/geometry.ts:1` imports
`../../scene/palette.js` — the `scene/` import the law exists to forbid —
invisible twice over, because the walk never enters the directory *and* the
pattern is hardcoded one level up. `compare/` (7 files) is governed by no such
law at all. Distinct from [#245](../../issues/245), which is the *server* lab's
structural boundary.

**3. No test crosses the web↔server boundary — the structural reason #1
shipped green.** `api/label.test.ts:52` manufactures the header from
`app.capabilityToken`, a value the browser cannot read;
`recordings/RenameControl.test.tsx:26` injects a `fetch` double returning 200
unconditionally. Zero files under `packages/web/src` reference `buildApp`, no
web test imports server source, and no `e2e/` or `integration/` directory
exists. Any client/server contract mismatch — headers, status codes, body
shape, route paths — is invisible to all 3,412 tests. Not
[#244](../../issues/244), which is scoped to "instrumentation only".

### MEDIUM

**4. `mutating-calls-law.test.ts:169-173` pins the bug in #1.** It asserts
every `headers:` block in `label.ts` equals exactly
`'Content-Type':'application/json'`, so adding the capability header turns it
red. The law is not too loose here — it is too tight, on the wrong axis. It can
be tightened to a new fixed shape rather than loosened, so this is friction for
the fix, not evidence the law can be bypassed. Part of #249's landing.

**5. The app-wide mutating-calls law is blind to several non-fetch
mechanisms.** `replay/mutating-calls-law.test.ts:89-90` detects only
`/\b(?:POST|PUT|PATCH|DELETE)\b/` and `/\bmethod\s*:/`. `navigator.sendBeacon`,
`new WebSocket`, `new EventSource`, a lowercase JSX `<form method="post">` and
`img.src = '…?data='` all match neither and would stay green anywhere in
`packages/web/src`. `drawer/readonly.test.ts:69` bans that wider set — but only
within `drawer/`. Bears on the README's "nothing leaves the machine" claim.

*Correction to an earlier draft of this finding:* `XMLHttpRequest` is **not**
in the gap. Idiomatic `xhr.open('POST', …)` matches on the uppercase verb.

**6. `release.yml` publishes with four gates that never run.** The tag-triggered
path runs Checkout → Install → Build → Test → Typecheck → Packaging guard →
Version guard → `npm publish`, on `ubuntu-latest` only. Absent versus `ci.yml`:
**Lint**, the **boot smoke**, the entire **`pack-smoke` job** — the only thing
that installs the packed tarball into a clean project and boots it — and any
**macOS leg**, the one `AGENTS.md` names as carrying signal for path-shape bugs.
The packaging-guard heredoc is duplicated verbatim across both files
(`ci.yml:60-83`, `release.yml:44-68`), which is how this drifted.

Not [#225](../../issues/225), which is a defect *inside* pack-smoke; this is
that pack-smoke is not on the release path at all.

**7. The packaging guard and both boot smokes pass while shipping no
dashboard.** The guard (`ci.yml:75-83`) rejects unexpected files but never
asserts an expected one is present. Both smokes (`ci.yml:132-141`,
`scripts/pack-smoke.sh:140-146`) accept any `text/html` at `/` — which the
server's own "the dashboard hasn't been built" placeholder
(`server/build-app.ts:74-85`) also satisfies. `cli/doctor.ts:270` already makes
the right assertion (it checks for `index.html`) and neither smoke calls it.

Wider than first stated: `build-app.ts:74` gates on `existsSync(webDistDir)`, a
*directory* check, so an empty-but-present `dist/` takes the static branch and
404s — a second failure mode both smokes also miss.

**8. `scripts/pack-smoke.sh` destroys its own cleanup trap — widens
[#225](../../issues/225).** `:22` arms `trap 'rm -rf "$WORK"' EXIT`; `:99`
**replaces** it with a kill trap inside `boot_and_check`; `:152` removes all
EXIT traps. `boot_and_check` is called three times (`:157-159`), so after the
first call there is no EXIT trap at all. `$WORK` — four tarballs, a full
`npm install` tree, three git repos — leaks on **every** run including a clean
pass, and a failure in the `spaces`/`unicode` checks leaks the live server too.

#225 prescribes *adding* a trap; the accurate fix is that one already exists and
is being destroyed rather than restored.

**9. The drawer's read-only law does not cover one of the drawer's four tabs.**
`drawer/readonly.test.ts:23` greps `DRAWER_DIR` only, but `drawer/index.tsx`
renders `WhySurface` from `packages/web/src/why/` — the WHY tab, real drawer
surface, outside the grep. `why/` is clean today (no `fetch(`, no HTTP verb, no
`/api/` path), so there is **no live violation**; the finding is that the law's
stated scope ("whatever the drawer grows into") is narrower than claimed. A
cross-directory gap that recursion alone would not close.

## What came back clean

Recorded so the negative results are on the record rather than ambiguous:

- **"Nothing leaves the machine" holds** for the observer. No `fetch(`,
  `node:http(s)`, `net.connect`, `new WebSocket` or `http.request` in any
  non-test file under `packages/server/src` or `packages/core/src`. All three
  `listen` calls pin `host: '127.0.0.1'`. The OTLP receiver is a route on the
  same loopback app, not a second socket. *(The laboratory's `npm install` on
  fork is a real, documented exception — see the fix section.)*
- **Test hygiene is genuinely strong.** Zero `.skip` / `.only` / `.todo` across
  227 test files, and exactly two assertion-free `it()` blocks
  (`scene/perf.test.ts:998`, `:1002`), both deliberate measurement emitters.
  For a 60k-line test corpus that is an unusually clean result.
- **Zero real TODO/FIXME debt** in `packages/*/src` — every apparent match is
  the `TodoWrite` tool name.
- **`/api/transcript` path handling is well defended** — attribution required,
  `isSafeSessionId` gates the id *before* any `path.join`, `isPathContained`
  re-checks the joined result. No traversal found.
- **`scripts/pack-smoke.sh` is a real gate**, not a rubber stamp: four tarballs,
  installed into an `npm init -y` project outside the repo, executed via both
  `.bin/` and `npx --no-install`, booted against three watched-path shapes
  including spaces and non-ASCII. Findings #6 and #8 are about where it runs and
  how it cleans up — not about the quality of what it checks.

## Corrections made during this audit

Kept rather than deleted, so the record stays honest about what was believed:

1. **A finding was retracted outright.** An earlier draft claimed
   `scripts/gate.sh:23-24`'s `clean()` discards a lane's lockfile and then
   merges its `package.json`, ranked High. **This is wrong.**
   `git checkout -- <path>` does not revert a *committed* change — verified by
   experiment — so `clean()` only discards uncommitted npm-install churn, which
   is exactly what [#226](../../issues/226) documents and is correct behaviour.
2. **A `docs/adr/` finding is resolved upstream**, not by this audit.
3. **A remote-mismatch finding was withdrawn.** `git remote -v` names
   `KelliherL/rhizomorph` while the board is `launchpad-26/rhizomorph`; this is a
   repo transfer with a working redirect, not a wrong-repo hazard.

## Fixes for tracked findings

**#1 / [#249](../../issues/249) — deliver the token, and correct the doc.**
There is no delivery mechanism that both makes the shipped button work and
preserves `api/security.ts:1-15`'s stated threat model: the token names "another
local process" as the attacker, and every in-band delivery is readable by
exactly that attacker. Pick one honestly rather than shipping a mechanism whose
comment overclaims.

Proposed: inject `<meta name="rhizomorph-capability" …>` into `index.html` at
serve time in `server/static.ts`, read it in one new
`web/src/recordings/capability.ts`, and widen `LabelFetchLike` to the two-header
shape. **Not `/api/meta`** — both are equally readable by a local process, so
neither wins on the threat model, but `/api/meta` is a JSON contract other
tooling scrapes and `ci.yml:124` already `cat`s it to the build log, which would
print the token on every CI run. *(Independent reason: [#255](../../issues/255)
is concurrently editing that route.)* Out-of-band delivery is the only option
that honors the doc, and it makes the shipped button unusable — so reject it and
**write the ADR that says so**, then rewrite `security.ts:26-32`, which today
promises a follow-up this closes differently than it implies.

Blast radius: finding #4's law must be amended — as a *tightening* to a new
fixed two-header shape, landed as its own reviewable commit, never folded
silently into the implementation. Dev-mode gap to check: `vite dev` serves
`index.html` itself, so saves would 401 in dev.

**#8 / [#225](../../issues/225) — correct the diagnosis, then fix.** #225 asks
for a trap to be *added*; one exists and is being destroyed. Proposed: one
accumulating pid list and a single trap that is never removed —

```sh
PIDS=()
cleanup() { for p in "${PIDS[@]:-}"; do kill "$p" 2>/dev/null || true; done; rm -rf "$WORK"; }
trap cleanup EXIT
```

`boot_and_check` appends to `PIDS` instead of replacing the trap at `:99`, and
`trap - EXIT` at `:152` is deleted. Save-and-restore of the outer trap was
considered and rejected: fragile quoting, and it still leaves a window where
`$WORK` is unprotected.

**#12 / [#276](../../issues/276) — one sweep, not two.** #276 already sweeps
`README.md`, `docs/user-guide/` and `docs/telemetry.md` for commands that fail
for clone users. The mechanical half of finding #12 belongs there: extend the
same sweep to assert every `docs/….md` pointer resolves on disk, and **ban glob
pointers outright** (`docs/prd*.md` cannot be checked, which is precisely why
two survived). The eight one-line rewrites stay a separate commit. In
`mutation-guard.ts:9`, name `cli/run.ts` and `cli/replay.ts` **without line
numbers** — they rot the same way.

## Fixes for untracked findings

**#2 — recursive walk, depth-independent patterns, and a ruling.** Making the
walk recursive fails immediately, because the tree holds two contradictory
readings: `lab/LabPage.tsx:125` says the lab "may never" import `../scene/` and
hand-stringifies an `Ink` to avoid it, while `lab/branching/geometry.ts:17`
imports the palette and documents that as deliberate. So this needs a decision,
not a regex. Proposed: recurse (reusing the `visit()` already proven at
`mutating-calls-law.test.ts:71-88`), raise the vacuity floor from `>3` to `>=15`,
make patterns depth-independent (`/from ['"](?:\.\.\/)+scene\//`), delete the
drifted two-level copy in `launch/explicit-invocation-law.test.ts:66-71`, and
carve out `scene/palette.js` by name with a positive assertion that it is the
only `scene/` import in `lab/`. A colour table carries no fleet state, and
forking it gives two drifting palettes — which `geometry.ts:17` already names as
the thing not to do. Run the patterns against `compare/` (7 files, currently
ungoverned) **before** committing; if it is dirty that is a second finding, not
a reason to narrow the law. Say plainly in the commit that this is a law
amendment that strengthens net coverage in exchange for one named exception.

**#3 — a contract workspace.** New private `packages/contract/` whose tests boot
`buildApp(ctx)` and hand the **real** web client a `fetch` backed by
`app.inject`. The load-bearing property is that headers come from the web module,
not the test — which is exactly why `api/label.test.ts:52` did not catch #1.
Cover all three `MUTATING_MODULES` entries, plus a law that every entry has a
contract test. Chosen over Playwright to stay an operation-count oracle with no
sockets, ports, browser download or timing — Playwright would become the slowest
gate in the repo and reproduce the gate-tax flake. Chosen over cross-package
relative imports because `@rhizomorph/web` is `private` with no `exports` map.

**#5 — a second, separate `it`.** Ban `sendBeacon|new WebSocket|EventSource` in
*every* file, rather than widening `MUTATING_VERB_RE`: these are allowed in zero
files, not three, and folding them into the "exactly three files" assertion
merges two rules with different allowlists into the looser one. Document
`img.src` as a known accepted gap — any regex broad enough to catch it
false-positives on legitimate image rendering. Do **not** dedupe against
`drawer/readonly.test.ts:69`; it is narrower in scope and also bans
`child_process`/`eval`.

**#6 — make release depend on CI, don't re-implement it.** Extract
`build-test-boot` and `pack-smoke` into `.github/workflows/verify.yml` with
`on: workflow_call`; both `ci.yml` and `release.yml` call it, and release keeps
only the version guard and `npm publish`. Copying the missing steps across is
how this drifted — the guard heredoc is *already* duplicated verbatim. Note
`workflow_call` does not inherit secrets by default; `verify.yml` needs none.
**Sequence after #8**, or every release leaks a server.

**#7 — assert the dashboard, not just HTML.** In both smokes, replace the
`content-type` check with a body assertion (`<div id="root">`) plus a fetch of
one hashed asset — that also catches the empty-`dist/` 404 case. Give the
packaging guard a `required` list of regexes alongside `allowed` (a file *count*
passes vacuously when the wrong N files ship). Have `pack-smoke.sh` run
`npx --no-install rhizomorph doctor` in the installed tree, reusing
`checkWebBuild` rather than reimplementing it — that covers the installed
artifact, which a tarball manifest cannot see. *(Adjacent:
[#253](../../issues/253) is about to expose the same checks as
`GET /api/doctor`.)* **Sequence after #6** to avoid editing `release.yml` twice.

**#9 — a declared surface list for the drawer's law.** Walk `drawer/` plus an
explicit `DRAWER_SURFACES` list containing `why/`, and assert every relative
import in `drawer/index.tsx` that leaves `drawer/` resolves into either that
list or a declared `CONSUMED` allowlist — so the next escape fails with "add it
to DRAWER_SURFACES or to CONSUMED" rather than vanishing. A true import closure
was traced and rejected: it immediately pulls in `fleet/`, `app/StreamContext`
and `trace/model`, and `fleet/manifest.ts` legitimately fetches, so it would go
red for the wrong reason and be narrowed back within a week.

**#10 — `--force` on `export-record`.** Add `force?: boolean` to the options;
after the existing `isInsideRepo` check, refuse when `outPath` exists and
`force !== true`, naming `--force` in the message. Refuse-by-default over
prompting, because this is a non-interactive one-shot that may run in a script.
No law is touched — worth stating in the commit so it is not misread as a fence
change.

**#11a — delete three inert pragmas.** Replace each `eslint-disable-next-line`
with plain prose naming the same reason; both React ones already carry the real
explanation on the lines above, so the pragma line simply goes. Installing
ESLint permanently to legitimize three comments is the wrong trade.

**#13 — apply #2's recursive walk to both sibling laws**, plus a floor
assertion matching today's real file count. Zero behaviour change on landing;
the point is that the loss is silent by construction, and #2 proves it has
already happened once. Bundle with #2 and #9.

**#14 — interpolate rather than correct the word.**
`` describe(`… exactly ${MUTATING_MODULES.length} mutating calls …`) ``, so it
cannot drift again the next time a route is added.

**#15 — bump `actions/checkout` and `actions/setup-node` to v5** at all five
sites. Verify the min-Node matrix leg still resolves: `setup-node@v5` changed
default cache behaviour and dropped some older targets. SHA-pinning two actions

pinning is wanted it is an ADR covering every action.
