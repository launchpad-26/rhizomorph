# Testing strategy and quality review

**Verdict**
- The core architecture is right and well-executed: parsers are pure functions of captured text, `Exec` is genuinely injected (only 2 of 83 server test files touch `vi.mock`/`vi.fn()` at all), and the suite is unit-heavy by design for a tool whose real risk is external command output — a defensible shape, undermined only by fixture curation, not by test technique.
- CI is currently red on `main` and has been for the last 8 consecutive pushes (verified via `gh run list`), all failing the same `build-test-boot (macos-latest, current)` leg on the exact test the brief flagged — two "fix" commits landed on top of the still-red failure without re-running the matrix first. The matrix design is sound; the discipline of using it isn't.
- The "law test" pattern is a real strength where it checks things no type system can (forbidden HTTP verbs, PII-shaped values in checked-in fixtures, absence of a clock) and a false sense of security where it checks import graphs — `api/lab.ts:361` is a working, checked-in proof that one level of indirection defeats the "sole importer" grep today.

## Top findings, prioritized

**1. Root-cause the live CI failure — it's a one-line miss, not a flaky test.** `namespace-law.test.ts:582-657` fixed the *containment* check's canonicalization (`repoDir` vs `realpathSync.native`, commit `7a9219d`) but never applied the same fix to the *round-trip* check three lines above it: `realDataRoot = path.join(root, 'real-data')` (line 593) is never passed through `realpathSync.native`, so `registered.some(w => w.startsWith(realDataRoot))` (line 655) compares a raw `/var/...` path against git's always-native `/private/var/...` output and is unconditionally false on macOS. The evidence block added one commit earlier (`e73c9a7`) prints exactly this raw/native mismatch in its own failure message and still didn't get fixed. This is the same bug class as the two prior "fix(lab): canonicalize..." commits, attempted a third time, still incomplete.

**2. Main has been red for 8 straight commits.** `gh run list --branch main` shows every push since `1612a14` failing CI, isolated (`gh run view` on two of them) to `build-test-boot (macos-latest, current)` — every other leg (ubuntu×2, pack-smoke×4) is green. The matrix is doing its job; nobody is looking at it before merging on top. A red main trains reviewers to ignore red CI, which will cost a real regression eventually.

**3. The namespace-law "sole importer" check has a documented but real evasion, already in production.** `api/lab.ts:20-38` explains, correctly, why its dynamic `await import('../cli/index.js')` (line 361) satisfies the law's *spirit*. But `namespace-law.test.ts:143-157`'s check only greps for specifiers matching `lab/`, and `'../cli/index.js'` never does — so the mechanism can't actually distinguish "the one blessed reroute" from a second, unreviewed one added next month that does the identical `await import('../cli/index.js')`. Today there's genuinely only one such caller (verified: `grep -rn "cli/index" packages/server/src` shows exactly one non-test, non-comment call site), but nothing *asserts* that stays true. A dependency-cruiser reachability rule (which resolves the module graph, not text) would catch a second indirect caller; a plain grep cannot, by construction.

**4. Git fixtures are curated happy paths with two concrete, zero-coverage failure modes.** `git-collector.ts:261` runs `git status --porcelain` without `-z` or `-c core.quotePath=false`; `parse-status.ts:12-34` does no unquoting of the result. `core.quotePath` defaults to `true`, so a non-ASCII filename comes back as a literally quoted, octal-escaped string (`"na\303\257ve.txt"`) and that is what ships as the file path — untested, because no fixture in `packages/server/src/collectors/git/fixtures/status/` contains a non-ASCII or quoted name. Separately, `worktree-list/all.txt` tests `detached: true` only on a *secondary* worktree (line 13-15); the main worktree (always record #1, per git) is never exercised in a detached-HEAD shape, and `parse-worktrees.test.ts` never constructs one.

**5. tmux's tab-delimited parser documents its own risk honestly, but it's still unverified.** `list-panes.ts:7` states "none of these fields can contain a tab" as an explicit assumption rather than hiding it — better practice than the git gap above — but `pane_title`/`window_name` are attacker- or program-controlled strings (OSC title-setting) that legitimately can contain a tab, and no fixture tests that case; `parseListPanes` currently throws on it (`list-panes.ts:34-38`), which `poll-loop.ts:96-117`'s try/catch downgrades to a `collector.error` for the *whole tick* rather than skipping just the one pane.

**6. The otel collector is the model the others should copy.** `collectors/otel/fixtures/` includes `logs-malformed.json`, `metrics-malformed.json`, and `metrics-bad-datapoint.json` — deliberately broken shapes, checked in and exercised. Nothing equivalent exists for git, tmux, or workmux; this is a team habit that exists in one place and hasn't spread.

**7. No browser-level e2e; the one true end-to-end check lives in CI, not vitest, and is thin but real.** `.github/workflows/*.yml`'s boot-smoke step starts the packed server, hits `/api/meta` and `/`, checks content-type, and shuts down cleanly — a legitimate integration check of the whole packaging pipeline, appropriately placed outside the unit suite. There is no test of the full poll → recorder → SSE → web-render path.

**8. `fixture-hygiene-law.test.ts` is the pattern's best use.** It greps checked-in OTel fixtures for real-looking `user.email`/`organization.id`/etc. values (lines 20-30) — a values check no import-graph tool (Biome, dependency-cruiser) could ever replace, because the violation isn't a forbidden import, it's a forbidden *literal*.

**9. `marks.test.ts` (3,772 lines) is large because `marks/` is large (4,446 lines across 10 files), not because it's padded.** Zero `toMatchSnapshot` calls; every one of 150+ cases asserts specific roles/positions against named pathology fixtures. The one real smell is `HEAVY_CASE_TIMEOUT_MS = 20_000` (lines 122-136), raised after documented CI contention (693ms quiet vs 5.5-7.2s alongside sibling lanes) — a resource-sharing symptom worth watching, not a bug in the test.

**10. Host coupling is broad but matches the CI matrix that exists — until it doesn't.** 14 server test files shell out to a real `git` binary, 41 touch `os.tmpdir()`/`mkdtemp`. Fine given ubuntu+macos coverage today, but finding #1 is exactly what this coupling produces the moment a new OS/tmpdir shape shows up — expect more of the same bug class, not less, as the matrix grows.
