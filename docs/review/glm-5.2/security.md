# Security review

**Overall risk verdict: MEDIUM.** The observer half is genuinely read-only and the binding/access-control design is sound. The browser/repo/agent attacker is well-defended against (loopback bind, Host/Origin guard, no CORS, React-escaped rendering, argv-only subprocess calls, double-gated path traversal checks). The laboratory half, however, contains one real command-injection latent in an unsanitized `model` string that is interpolated into a shell command, and the two most consequential mutating routes are the two that skipped the capability-token control.

---

**SEV-2 — `packages/server/src/lab/fork.ts:120` — unsanitized `model` interpolated into a shell command string — exploit path — fix.**
`workmuxAddArgv` builds `argv.push('-a', \`bash scripts/lane-agent.sh ${treatment.model}\`)`. The `model` value originates from the HTTP request body at `POST /api/lab/launch` (`packages/server/src/api/lab.ts:415` `parseLaunchRequestBody` only `trim()`s it; `cli/lab-fork.ts:100` only rejects empty), flows through `launchExperiment` → `runCli(['lab','fork',...,'--model',model])` → `dispatchFork` → `workmuxAddArgv`. The `-a` argument is a *shell command string* that workmux/tmux executes (per `scripts/lane-agent.sh:11` and the documented contract), so a `model` of `x; touch /tmp/pwned` becomes `bash scripts/lane-agent.sh x; touch /tmp/pwned` and the second command runs. `execFile` is argv-form, so there is no shell at the rhizomorph layer — the injection happens at the workmux pane-command layer, which is exactly the contract this code is constructing. A cross-origin browser is blocked by the mutation guard's Host check, but a local malicious process (or a future XSS / pre-fill path) reaches this with no capability token (see next finding). Fix: validate `model` against a strict allowlist/charset (`^[A-Za-z0-9._:-]+$`) before it ever enters the `-a` string, and/or pass it as a separate positional to `lane-agent.sh` rather than concatenating it into one shell string.

**SEV-2 — `packages/server/src/api/lab.ts:532` and `packages/server/src/api/rotate.ts:25` — mutating routes do not require the capability token — exploit path — fix.**
Only `/api/label` adopts `requireCapabilityToken` (`api/label.ts:38`). `security.ts`'s own doc admits adoption is "incremental," but the routes left for later are the dangerous ones: `/api/lab/launch` shells out to `workmux` (and is the gateway to the model injection above), and `/api/rotate` mutates the recording on disk. Both are protected only by the app-wide Host/Origin/Content-Type guard, which closes the browser/CSRF/DNS-rebinding half but explicitly *does not* close the "another local process, or a forged-Origin rebind" half (`security.ts` says so). A local process can trivially send `Host: 127.0.0.1` and no `Origin` and reach either route. Fix: apply `requireCapabilityToken(ctx.capabilityToken)` as `preHandler` to both, as already designed.

**SEV-3 — `packages/server/src/server/static.ts:33` — path-containment check uses `startsWith(root)` without a separator — exploit path — fix.**
`requested = path.resolve(root, request.params['*'])`, then `if (!requested.startsWith(root))`. A wildcard value of `../<sibling>` resolves to a directory whose name shares `root`'s prefix without a trailing separator: with `root = /…/packages/web/dist`, `* = ../distsecret/secret` resolves to `/…/packages/web/distsecret/secret`, which `.startsWith('/…/packages/web/dist')` is `true`, so a file under any sibling directory whose name begins with `dist` is served. Not currently exploitable (no such sibling exists), but the pattern is the classic prefix bug. Fix: require `requested === root || requested.startsWith(root + path.sep)`.

**SEV-3 — `packages/server/src/api/otel.ts` (`foreignInstance`), `cli/run.ts:~92` — OTLP "instance" check is a timestamp, not a secret — exploit path — fix.**
The accepted-instance identity is `ctx.recorder.sessionId`, and for a fresh session that is `String(Date.now())` (`run.ts`). It is published unauthenticated on `GET /api/meta` (`api/meta.ts:130`). The `/v1/metrics|logs|traces` POST routes (covered by the mutation guard, so cross-origin browsers are blocked) accept any body whose resource blocks carry that id — a local process can read it off `/api/meta` (or guess to the second) and inject forged telemetry events into the record. Low integrity impact (telemetry is already attacker-influenceable by design), but it defeats the "one repo, one Rhizomorph" claim for the local-threat model. Fix: require the capability token on OTLP POSTs as well, or derive the instance id from secret entropy rather than a wall-clock timestamp.

---

**Done correctly.**
- All observer subprocess calls use `execFile` argv form only, never a shell string (`server/exec.ts:11`); git branch names that could start with `-` only ever appear inside combined range-spec argv elements (`${mainBranch}...${branch}`, `git-collector.ts`) or as real refnames git itself refuses to let begin with `-` (`judge/mergetree.ts:72`), so no flag injection in the collectors.
- Path traversal is double-gated for transcripts: `isSafeSessionId` (`path.basename` equality + NUL refusal) plus `isPathContained` (`transcript-attribution.ts`), and session files are addressed via `sessionFileName(Number(sessionId))` which coerces to `session-NaN.jsonl` (`session-log.ts:91`) — `/api/sessions/:id/events` cannot escape `sessionDir`.
- Lab write fence enforced at runtime (`assertInsideLabWorktrees`, `lab/paths.ts`), symlink-resolved containment check.
- No XSS: `grep` finds zero `dangerouslySetInnerHTML`/`innerHTML`/`eval` in non-test web source; all repo- and agent-derived text (transcript prose, tool hints/results, commit subjects, branch names) is rendered as React JSX text children, escaped by construction; no markdown/HTML renderer.
- The capability token is never logged, persisted, or echoed (`security.ts`); no OTLP headers or secrets are recorded beyond the agent conversation data the tool exists to show.
- `SECURITY.md`'s "read-only observer" and "127.0.0.1-only" claims hold against the code; its "never sends a keystroke to an agent" claim holds for the observer but is *violated* by the laboratory's `--launch` path (which is by design, documented in README) — and that path is where the model-injection finding lives.
