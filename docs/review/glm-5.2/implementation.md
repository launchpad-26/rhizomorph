# Implementation review

- **The richest collector (sessionlog) is the only one with no resilience/self-heal wrapper**, so a single transient `stat`/`git` failure permanently kills it for the whole session while every other collector recovers.
- **Thrown parser exceptions bypass the resilience policy entirely** — they become one `collector.error` per 2 s tick forever, with no latch, backoff, or disable, because `withResilience` only reacts to `collector.disabled` events.
- **Round-trip and integrity are sound** (record build/read/verify re-derive the same chain, lenient unknown-line handling is consistent); the leaks are in the live server path, not the portable format.

## Findings (ranked likelihood × impact)

- **packages/server/src/cli/run.ts:129 — sessionlog collector is never wrapped in `withResilience`/`withResumeReconciliation`.** `loadCollectors` (collector-loader.ts:57) wraps git/tmux/workmux/judge; sessionlog is appended raw at run.ts:129. Its own `disable()` (collector.ts:255) latches `disabled:true` and every later poll early-returns (collector.ts:76). Scenario: the watched repo is renamed/moved mid-session, or `~/.claude/projects` sits on a briefly-unresponsive mount → one failed `git worktree list` / `stat` and the transcript organ (identity, liveness, telemetry) is dead until process restart; a stale `collector.disabled` from the prior session is also never reconciled on boot. Highest-impact gap in the codebase.

- **packages/server/src/collectors/tmux/list-panes.ts:35,51 + packages/server/src/server/poll-loop.ts:106-111 — thrown parsers spam errors every tick with no backoff.** `withResilience` (resilience.ts:101) only short-circuits on a `collector.disabled` *event*; an exception propagates straight through it to `runTick`'s catch, which records `collector.error` and moves on. Scenario: a pane title or window name ever carries a literal tab, or tmux changes its `-F` output → `parseListPanes` throws on every 2 s tick → one error event per tick, forever, no disable, no retry interval. Same shape for `parseGitLog` (parse-log.ts:70) on one weird `--raw` line, re-firing each time that branch's head moves.

- **packages/server/src/recorder/session-recorder.ts:80,99,129 + packages/server/src/api/stream.ts:156 — unbounded in-memory buffer, O(n) per SSE connect.** Every `record()` pushes to `buffer`; `eventsSoFar()` returns `[...this.buffer]` and `/api/stream` calls it on every connect, then `resumeBacklog` (stream.ts:118) does `findIndex`+`slice`. Scenario: a multi-day session never rotated (the rotate path is operator-triggered only) holds tens of thousands of events; each new dashboard tab allocates a full copy plus a linear scan. The 46k-event case the #166 comment names is exactly the regressing workload. Rotation (`openSession`, line 115) is the only thing that ever clears it.

- **packages/server/src/collectors/workmux/collector.ts:92,110 — the status↔list join is keyed by the wrong field.** `listByHandle = new Map(listRows.map((row) => [row.branch, row]))` then `listByHandle.get(row.handle)`. The map is keyed by `branch`, looked up by `handle`. Scenario: any lane whose branch name ≠ its worktree handle (branch `feature-x` on worktree `2-core`) → `agent.status` events are emitted with `branch: null, worktreePath: null` every poll. Only the fixture's branch==handle coincidence hides it.

- **packages/server/src/collectors/git/parse-status.ts:23-31 — porcelain v1 paths with spaces/unicode stay C-quoted.** `rest = line.slice(3)` is taken verbatim; git wraps such names in `"…"` with octal escapes and there is no unquote pass. Scenario: any dirty file whose path contains a space → `DirtyFile.path` is `"my file.txt"` including the literal quotes; rename-split on `' -> '` also mis-splits a quoted name containing that arrow. Collision/touch matching by exact path then misses, and the drawer shows quotes.

- **packages/server/src/collectors/git/git-collector.ts:190 — rebased/force-pushed branches emit no `commit.landed`.** `loadNewCommits(context, prevBranch.head, ref.head)` runs `git log fromHead..toHead`; once `fromHead` is unreachable (rebase/amend rewrote history) `git log` fails → returns `[]`. Scenario: a worker force-pushes a rebased branch → the new commits never appear as `commit.landed`; `branch.updated` still fires so it looks like movement with no landing.

- **packages/server/src/collectors/sessionlog/tail.ts:26 — `readNewLines` never recovers from truncation/rotation.** `if (info.size <= offset) return { lines: [], nextOffset: offset, … }`. Scenario: a session JSONL is ever replaced smaller (external rotation, manual edit) → `offset` stays past EOF, every later poll reads nothing and the lane's liveness state machine stalls on a dead file. Files normally only grow, so likelihood is low, but the failure is silent and permanent.

- **packages/server/src/server/poll-loop.ts:122-133 — slow ticks silently stretch cadence.** `tick()` dedupes onto `inFlightTick`; `setInterval` fires `tick()` which returns the in-flight promise and drops. Scenario: a 20-pane tmux fleet spawns N+1 sequential `capture-pane` subprocesses per tick (collector.ts:78); once that exceeds `intervalMs` (default 2000), scheduled polls are dropped rather than queued — no error, just effective cadence far below configured. No parallelism across collectors either (runTick loops sequentially).

- **packages/server/src/api/otel.ts:79-87,128-136 — malformed foreign OTLP posts still write to our log.** The malformed branch records `collector.error` events *before* the `foreignInstance` check, and the refusal throttle doesn't cover the 400 path. Scenario: a misconfigured foreign exporter sending garbage writes one `collector.error` per request into our session log, unthrottled. Low volume, but pollutes the recording the audit is meant to keep clean.

- **packages/core/src/record/schema.ts:18 — `schemaVersion` is `z.number().int().positive()`, not pinned to `RECORD_SCHEMA_VERSION`.** `parseRecord` accepts a v2 record; `verifyRecord` (verify.ts:48) rebuilds the genesis seed with whatever version arrived, so it verifies clean and treats newer events as `unknown`. By design (lenient federation), but worth noting there is no explicit "this reader is from era N" guard — a malformed-on-purpose v2 file verifies as intact.
