# Testing strategy and quality review

- **Verdict 1:** The suite's spine — pure parsers pinned against *real captured output*, a single `Exec` injection seam, Fastify `inject` integration — is genuinely good and correctly aimed at the actual risk (parsing other tools' output). The "law test" layer on top is thoughtful but half of it should be lint, and one of its headline guarantees is already evaded in-tree.
- **Verdict 2:** Fixture coverage is curated happy-path-plus-a-bit: real gaps exist exactly where the parsers are most fragile (C-quoted/unicode git paths, tabs in `pane_current_path`, detached HEAD on the main worktree).
- **Verdict 3:** Suite health is solid (89s wall, near-zero mocking) but the one red test is a symptom, not bad luck: the live law tests are host-dependent (git canonicalization × TMPDIR symlinks × Node version), and CI's green badge does not cover a developer's machine.

**1. Strategy.** The inferred philosophy: parsers are pure and fixture-driven (`collectors/tmux/list-panes.test.ts:11` parses captured `list-panes.real.txt`; sessionlog fixtures are versioned real captures with provenance, `claude-code-2.1.222-*.jsonl` + `CAPTURE.md`); everything shelling out goes through one argv-only `Exec` seam (`server/exec.ts:9`); routes are tested through `app.inject` (`api/lab.test.ts:40`). Distribution: 114 web / 83 server / 30 core test files. That is the right pyramid for this product. What is *not* tested end to end: the browser. Canvas is never executed (jsdom has no context — acknowledged at `marks.test.ts:1834`); the only full-system check is CI's bash boot smoke (`ci.yml` "Boot smoke"). For a read-only dashboard that's defensible, but the paint path (`marks.test.ts:1964` uses a stub context) means a runtime-only canvas bug ships green.

**2. Law tests.** What they genuinely buy: invariants no behavioral test can prove — "no observer imports the lab" (`namespace-law.test.ts:147-158`), "no `setInterval` under `lab/`" (:288), fixture PII hygiene (`fixture-hygiene-law.test.ts`). The self-checking "detector bites" fixtures (:137-146, :252-260) are excellent practice. How they fail: `targetsLab` (:107) is a path-text heuristic — rename `lab/` and the law passes vacuously; `readonly.test.ts:37` greps bare words, so a comment saying "never POST" fails the build (false positive); and reachability is not imports. **Worked example, verified:** `api/lab.ts:361` does `await import('../cli/index.js')` and `POST /api/lab/launch` thereby reaches `fork.ts` over HTTP. The sole-importer assertion at `namespace-law.test.ts:159-165` stays green because the law counts *direct* imports of `lab/`, and `api/lab.ts` never names it — yet "explicitly-invoked only" now means "any HTTP client." The law's own header (:24-27) promises exactly what no longer holds. **Biome `noRestrictedImports` is the correct tool for the import-confinement half** — it is absent from `biome.json` (linter is a hand-picked rule list). It is AST-aware, rename-safe, and runs in `npm run lint`, which CI already enforces. Keep grep-laws only for what lint can't express (git argv verbs, `setInterval`, fixture PII).

**3. Fixtures.** Good: empty output covered (`git/fixtures/log/empty.txt`, `workmux/fixtures/status-empty.txt`, blank-line test `list-panes.test.ts:31`); missing binaries covered (`tmux/collector.test.ts:24-29` ENOENT, `workmux/collector.test.ts:104`); malformed OTLP covered (`metrics-malformed.json`). **Zero-coverage real failure modes:** (a) **unicode/C-quoted git paths** — with default `core.quotepath`, `git status` emits `"caf\303\251.txt"`; `parse-status.ts:25-27` splits on `' -> '` and would emit the quoted literal as the path. No fixture, no unquoting code. (b) **tab inside `pane_current_path`** — `list-panes.ts:8` asserts by fiat "none of these fields can contain a tab," but a directory named `a<TAB>b` yields 8 fields and `parseListPanesLine` **throws** (:34-38); no test shows the collector surviving that throw. (c) **detached HEAD on the main worktree** — `worktree-list/all.txt` detaches only a linked worktree; the main is always `branch refs/heads/main`. Everything downstream that assumes "main worktree ⇒ branch" is unpinned.

**4. Over/under-tested.** `marks.test.ts` is 3,772 lines / 159 `it`s — one file asserting a rendering aesthetic; it should be split per concern. Its frame-budget test is self-admittedly vacuous: "The only claim made about the timing: it produced a number" (`marks.test.ts:1855`, `expect(whole).toBeGreaterThan(0)`) — honest, but it's a benchmark wearing a test costume; the sibling vertex-cap assertion (:1860) is the real test. Untested-but-load-bearing is thin: `core/src/events/upcast.ts` is a deliberate identity chokepoint covered indirectly via `reduce.test.ts`; `server/context.ts` is an interface. No constants-against-themselves found elsewhere.

**5. Suite health.** Reproduced: 89s wall, 3411/1, failing at `namespace-law.test.ts:655` — the vacuousness guard compares raw `/var/...` against git's `/private/var/...` canonical output (evidence shows Node v24.15.0). **The macOS/CI gap is real but inverted:** CI *does* run macos-latest and is green, while a dev's Mac (different git/Node canonicalization behavior) is red. Host dependence is otherwise well-managed: real git via `execFileSync` in lab/judge/cli tests, `mkdtemp` hermeticity, no tmux required. CI runs exactly `npm test` plus build/typecheck/lint/pack-guard/boot-smoke/pack-smoke on ubuntu+macos × node min/current — CI runs *more* than a developer, which is right. No Windows leg despite `path.sep`/`realpathSync.native` platform-sensitivity.

**6. Mocking.** Exemplary: exactly 3 test files use `vi.mock`/`vi.fn`. The `Exec` seam is the universal substitute; nothing tests its own mock.

**Top 10, prioritized:**
1. Fix the `:655` guard to canonicalize both sides — it reds the suite on exactly the host class it documents.
2. Move import confinement to Biome `noRestrictedImports`; delete the grep half of `namespace-law`.
3. Close or formally accept the `api/lab.ts:361` reachability hole (law currently proves "no direct import," not "HTTP can't fork").
4. Add C-quoted/unicode fixtures for `parse-status`/`parse-worktrees` + unquoting.
5. Decide and test tab-in-`pane_current_path` behavior; verify the collector survives a parser throw.
6. Detached-HEAD-on-main-worktree fixture.
7. Split `marks.test.ts`; demote the perf "test" to a benchmark script.
8. Anchor `readonly.test.ts` regexes to `fetch(` call sites, not bare verb words.
9. Add a Windows CI leg or declare non-support explicitly.
10. One browser-level smoke (Playwright, paint once, assert no throw) or document the gap.
