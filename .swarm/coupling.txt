# Coupling points — files a fence cannot see coming.
#
# `scripts/fence-lint.sh` reads this before a wave is dispatched. For each path
# below it asks whether any issue in the wave fences it, and warns when the wave
# is working inside its subtree without owning it. Until this file existed the
# lint exited 1 with "create one", so the repo's pre-dispatch check was dead.
#
# FORMAT, one entry per line, exactly as fence-lint.sh parses it:
#
#     <path>  # why it couples
#
# One path per line — the path is everything before the first `#`, trimmed, and
# the whole rest of the line is the reason, printed verbatim in the warning. A
# line starting with `#` in column 1 is a comment; blank lines are skipped. An
# entry with no reason is worse than no entry: the reader has to go and find out
# what couples before they can judge the warning, and a warning nobody can judge
# is a warning everybody learns to skip.
#
# What belongs here: a file that a change ELSEWHERE forces an edit to. Not a
# file that is merely popular. The test is whether a lane could do everything
# right inside its own fence and still redden this file.

# ── exact counts and cross-directory anchors in theme/ ──────────────────────
# These fail in both directions. A count asserted with `.toBe()` breaks when the
# number falls as readily as when it rises, so a lane that legitimately RETIRES
# a literal reddens a test it never touched and has no fence to fix it in.
packages/web/src/theme/tokens.test.ts  # RAW_PIXEL_SIZES is an exact `.toBe(225)` over the whole package, so retiring a pixel literal fails it exactly as adding one does; it also holds STATUS_RING_ALLOWLIST, whose entries are snippet-anchored into app/StatusBar.tsx and break if that line is reworded
packages/web/src/theme/legibility.test.ts  # its ALLOWLIST is snippet-anchored into drawer/Conversation.tsx — rewording the matched line fails this test from a directory the lane never entered
packages/web/src/theme/kind.test.tsx  # HAND_SPELLED_TAGS greps the whole package for hand-spelled kind tags and asserts BOTH an exact count and an exact file Set (`why/WhySurface.tsx`), so spelling a kind anywhere new, or cleaning one up, lands here

# ── the one-storage-file law in settings/ ───────────────────────────────────
packages/web/src/settings/registry.ts  # every persisted preference is declared here and this is the ONLY module in packages/web/src permitted to name localStorage or sessionStorage — so any new persisted preference, anywhere in the app, forces an edit to this file
packages/web/src/settings/coverage-law.test.tsx  # enforces that law by sweeping the WHOLE web package for browser stores and `rhizomorph.*` keys, and by equating the registry's ids with the controls the settings page renders — it reddens for a persisted value added in any directory

# ── the scene palette, mirrored in both directions ──────────────────────────
packages/web/src/scene/palette.ts  # mirrors the hexes in theme/theme.css, and scene/salience.ts, pulses.ts, motes.ts, motion.ts, heart.ts, lab/branching/geometry.ts and fleet/sigils.tsx all read or mirror it in turn — a theme edit and a scene edit in the same wave meet here
packages/web/src/scene/palette.test.ts  # parses theme/theme.css off disk AND imports across four directories — panels/attention/, settings/, theme/ and scene/ — so a change in any of them can redden a test no lane in that subtree fenced

# ── shared test doubles and allowlists ──────────────────────────────────────
packages/web/src/App.test.tsx  # eight `vi.mock`s of the lazily-loaded panels (panels/attention, burn, fleet, ledger, collisions, feed, plus replay/ and scene/) — adding, renaming or moving a lazy panel forces an edit here, and it sits in nobody's declared fence
packages/web/src/drawer/readonly.test.ts  # the CONSUMED allowlist — every relative import leaving drawer/index.tsx must resolve into DRAWER_SURFACES or be named here, so a new dependency of the drawer lands in this file

# ── the concierge namespace law's declared-importer seam ────────────────────
packages/server/src/concierge/namespace-law.test.ts  # clause 1's "no file in either package reaches the concierge module" sweep skips every file already inside concierge/, so a test elsewhere that needs a real concierge export (reverseProjectSlug, etc.) either gets moved INTO concierge/ (no edit here) or gets declared in ALLOWED_IMPORTERS (an edit here) — #47 found this only by first hitting the wrong choice (a computed import specifier in worktree-slug.test.ts) and moving the test settled it without touching this file, but the next lane facing the same fork should read this before picking the specifier dodge again

# ── the forward-transform law's reverse-direction discriminator ─────────────
packages/server/src/collectors/sessionlog/forward-transform-law.test.ts  # its check-3 discriminator quotes concierge/repos.ts's reverse-walk re-encode class verbatim, in both the file doc comment and two unit examples, to prove the detector does NOT convict the reverse direction — so a lane that changes that class in repos.ts (as #120 did) reddens nothing at runtime (the detector's own logic is class-agnostic) but leaves the quoted examples stale, describing a class repos.ts no longer has; #47 recorded the sibling coupling (namespace-law.test.ts) above while missing this one, which is why #120 records it now

# ── registration seams: one file every new thing must be added to ──────────
packages/server/src/api/route-class-law.test.ts  # it pins `expect(ROUTE_CLASSES.length).toBe(25)` AND `expect(routes.length).toBe(25)`, two exact counts asserted independently of the array itself so the walk cannot pass vacuously — which means ANY new route, registered anywhere under api/, reddens this file from a directory the lane never entered, and so does legitimately retiring one. It fails in both directions, like theme/tokens.test.ts. A lane adding a route must fence this file up front and reconcile the pins and the doc comment beside them in the same commit; #213 is blocked on #23 for exactly this reason
packages/server/src/server/collector-loader.ts  # the collectors are registered here by STATIC import, deliberately — a variable dynamic import like `import(`./${slug}`)` cannot be bundled by Vite/Rollup, and the file's own comment says so. Adding a collector anywhere therefore forces an edit to this one file, which sits in nobody's declared fence. NOTE the sibling that is deliberately NOT an entry here: server/collector-wrap-boundary.test.ts derives its set by walking the collectors directory and its own "sixth collector spliced in raw" case proves a new collector is picked up automatically — recording it would teach the next lane to edit a file that correctly needs no editing

# ── the one every lane touches without meaning to ──────────────────────────
package-lock.json  # any dependency change rewrites it, so two lanes adding a dependency in the same wave conflict at landing even though neither went near the other's files
README.md  # the trust document: prd8 ruling made it load-bearing, and it is anchored from many directions at once — the install identity (`manifest-law.test.ts` pins the repo URL), the support matrix (mirrors `.github/workflows/ci.yml`'s leg list), the route counts (mirror `api/index.ts`'s ROUTE_CLASSES), the CLI surface (mirrors `cli/index.ts`'s subcommands) and its own runnable grep recipes — so unrelated waves collide here and only ONE issue per wave may claim it

# ── gate.sh's own text, anchored into the law that checks it ────────────────
# Both entries below are the same coupling seen from its two ends. Cite ANCHOR
# TEXT, never a line number: these anchors have carried three different sets
# of line numbers within one milestone (wrong on `main` before prd45 wave 1,
# widened by wave 1, moved again by #119) — a registry entry pinned to a
# number for a file that moves is a registry entry that rots by construction.
scripts/gate.sh  # its timing set is DERIVED, never listed: a test opts in with a `// @gate-timing` marker comment or a `*.bench.test.ts` filename, found by grepping `packages/` rather than off a maintained list — so un-marking, renaming, deleting or merging away ONE timing test anywhere in the tree silently drops it from that grep, with no fence anywhere naming gate.sh. It fails the landing twice over: once when the discovered set comes back empty (the "timing pass matches ZERO files" guard), and again when the set shrinks below the floor recorded in `.swarm/timing-count` (a ratchet only a human clears; a rise is reported, never failed). A lane can do everything right inside its own fence and still break the operator's landing tool from a directory it never entered
packages/server/src/gate-honesty-law.test.ts  # anchors its gate.sh assertions on exact line TEXT pulled out of the tracked scripts/gate.sh, never by line number (some of the law's checks are deliberately independent structural or synthetic fixtures that read no gate.sh text at all — this entry is only about the ones that do), so rewording (or otherwise changing the wording of) any anchored gate.sh line throws at COLLECTION — "expected exactly one line ... found 0" — taking the WHOLE file's assertions out of service at once, not one red test; that is a different, and worse, failure than an ordinary shared-file warning. EXECUTED in a throwaway detached worktree: rewording gate.sh's `fail()` message line reproduces exactly that collection error. Separately, the law also PINS several derived counts over gate.sh's `VAR=$(...)` command-substitution assignments — how many exist, how many are flagged as structurally unchecked, and how the checked ones split between a same-line `|| fail` form and a next-line `_RC=$?` capture form — so adding, removing or restructuring one such assignment in gate.sh reddens packages/server/ from a directory the editor never entered, and the doc comment beside those pins must be corrected in the same edit, not just the numbers
