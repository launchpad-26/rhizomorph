# Coupling points — files a fence cannot see coming.
#
# `scripts/fence-lint.sh` reads this before a wave is dispatched. For each path
# below it asks whether any issue in the wave fences it, and warns when the wave
# is working inside its subtree without owning it. Until this file existed the
# lint exited 1 with "create one", so the repo's pre-dispatch check was dead.
#
# FORMAT, one entry per line, exactly as fence-lint.sh parses it:
#
#     <path>  # why it couples
#
# One path per line — the path is everything before the first `#`, trimmed, and
# the whole rest of the line is the reason, printed verbatim in the warning. A
# line starting with `#` in column 1 is a comment; blank lines are skipped. An
# entry with no reason is worse than no entry: the reader has to go and find out
# what couples before they can judge the warning, and a warning nobody can judge
# is a warning everybody learns to skip.
#
# What belongs here: a file that a change ELSEWHERE forces an edit to. Not a
# file that is merely popular. The test is whether a lane could do everything
# right inside its own fence and still redden this file.
